# BMS 随行20 · Android 0.3.5

纯手机版，面向一加 Ace 6 / Android 16、保锂安 LK8625-A66542（LR365V10_N031x）、20 串磷酸铁锂。沿用 Android 包名 io.bmsride.monitor。

## V0.3.5 更新
- 总览、行车 GPS、设备可左右滑动切换，相邻页切换、不循环；保留顶部点击导航。GPS 曲线内横滑用于查看历史，输入框手势保留；纵滑继续滚动。
- 总览只移除电池标题的 -20S 后缀，保留 20 串电芯显示；第一排顺序为电池电流、实时功率、总电压、电芯压差。
- BLE 无应用扫描过滤或数量截断，使用低延迟扫描（仍为8秒）。所有收到的广播设备按地址去重，已连接（如被扫描到）和 LK8625 可连接设备优先，同组按发现顺序。六行可视区内上下滑动，少于六个按实际数量显示；刷新信号不重建列表。系统权限、广播状态和扫描时间仍影响发现结果。保留原型号校验及断开按钮。
- GPS 和 BMS 数据解析、60分钟历史、能耗计算逻辑不变。

## V0.3.4 保留功能
- 导航只保留总览、行车 GPS、设备。20 串电芯并入总览，4 列 × 5 行圆角卡片，三位小数 V，顶部压差，最高黄色、最低青色；相同电压不作虚假高低标记。
- 设备页采用连接状态卡片、扫描按钮、扫描数量、名称/MAC/RSSI 及独立连接按钮。扫描结果无数量上限（V0.3.5 改为六行内部滚动）。只有 LK8625 名称匹配的设备可连接，其他 BLE 设备仍显示但标记不支持。保持原模型与协议校验。移除演示模式及停止监测服务按钮，同时删除模拟数据生成逻辑。保留断开 BMS 和可选手动容量设置；断开不会关闭后台 GPS，GPS 可在行车页暂停。
- GPS 车速左轴基础刻度 0、15、25、35、45 km/h，超过 45 自动扩展；右轴平均耗电独立自适应。近 60 分钟历史，按约 1Hz 采样，点击/横向拖动查看数值。时间窗保留于运行中的监测服务内存，非永久记录；停止服务/进程后丢失，重置里程同时清空。
- 手机 GPS 提供速度、里程、最高速度、精度；BLE BMS 提供电压、电流、SOC、电芯、温度等。耗电按 BMS 放电功率积分，平均耗电仅统计 GPS 与 BMS 均有效的配对区间，续航为剩余电量与平均耗电估算。数据失效不伪造曲线，缺测处断线，平均耗电至少需要 0.5 km 有效配对距离。GPS 关闭时不继续累计能耗。真实 BMS 协议仍须真机验证，MOS 温度、真实容量若未解码则显示空值（手动容量可作估算）。
- 未更改 BMS 读写请求或保护参数。历史 JK/JBD 解析器仍在内部测试，但无选择入口。

## GitHub Actions
1. 从 V0.3.4 更新时，将增量包解压后上传到现有仓库根目录，覆盖同路径文件；不要上传 ZIP 本身。
2. 手动编辑 `.github/workflows/build.yml`，替换为独立 `build-v0.3.5.yml` 的完整内容（网页上传可能跳过隐藏目录）。
3. Actions → Build Android APK v0.3.5 → Run workflow，main 分支。
4. 成功后下载 artifact `BMS-Ride20-Android-v0.3.5`，解压得到 `BMS_Ride20_Android_v0.3.5.apk`。
5. 默认临时构建密钥跨次不保证一致。签名不同时先备份旧设置，再卸载旧版安装；不要公开私钥。

本地构建：JDK 17、Gradle 8.9、Android SDK 35、build-tools 35.0.0、OpenSSL，执行 `bash build-packages.sh android`。

## 真机验证
车辆静止时操作。打开蓝牙、授权附近设备及精确定位，关闭其他 BMS App 的连接，扫描并选择 LK8625-A66542。核对总览 20 串与原厂软件数值，检查设备滚动、GPS 及断开状态。GPS 及 BMS 有效后才能计算实际平均耗电，不足 60 分钟只显示已有数据。不得将估算续航视为安全保障。

## 测试范围
纯 Java 协议模拟、TripHistory 60 分钟窗口、TripEnergy 联合能耗/缺失数据/断连/重置、UiRules 优先级与翻页规则测试、Java 语法解析（不含 Android API 类型检查）、Shell 与 YAML 语法检查已通过。尚未执行 Android SDK 编译和真机验证。
