# BMS 随行20 · Android 0.3.4

纯手机版，保锂安 LK8625-A66542（LR365V10_N031x），20 串磷酸铁锂，面向一加 Ace 6 / Android 16。包名 io.bmsride.monitor 保持不变。

## 本版更新
- 总览下方新增 4 列 × 5 行电芯卡片，显示 01–20、三位小数 V、压差；最高橙黄、最低青色（相同电压时不突出）。取消独立电芯标签。保留原 SOC、电气、三路温度、MOS 状态及告警。
- 设备：按参考图改为连接状态卡、扫描按钮、设备名称、地址、真实 RSSI（若已获得）、右侧连接状态按钮；整页可上下滑动。扫描全部可见 BLE 设备，仅允许 LK8625- 前缀设备连接，最终仍由原有型号及协议校验；不支持的设备明确标记。扫描不会主动断开当前 BMS 或清除骑行统计。保留断开 BMS、手动容量设置；移除演示模式及停止服务按钮，删除模拟数据生成路径。
- 行车 GPS：左车速轴 0/15/25/35/45 km/h，超过 45 自动扩展；右耗电轴独立动态 Wh/km。近 60 分钟的约 1Hz 采样，最多 3601 点；按真实时间定位，缺失样本保留间隙，可点击/横拖查询。历史保存在前台服务内存中，重启服务或重置行程会清除，不是永久记录。
- 车速、里程、定位精度来自手机 GPS；电压、电流、温度、电芯来自保锂安 BLE。平均耗电为本次行程 GPS 与 BMS 均有效区间的估算放电 Wh / 同区间 km（GPS 低速过滤，功率按相邻采样梯形积分，充电不计入放电能耗）。有效匹配里程少于 0.5 km、数据过期、未定位或未连接时，耗电与续航显示 —；不填假数据。续航还依赖 BMS 剩余容量或手动容量。MOS 温度尚未确认协议，未解码时显示 —。实际 BLE 读取精度仍需实测。
- 保留原协议解码与读取请求白名单，不修改电池参数。旧 JK/JBD 解析器仍留作内部历史代码，无入口。

## GitHub Actions
1. 已上传 V0.3.3 的仓库可使用 V0.3.4 增量 ZIP：解压后上传根目录中的 android、tests、build-packages.sh、README.md，保留目录结构。
2. 单独用 build-v0.3.4.yml 的全部内容覆盖仓库已有 `.github/workflows/build.yml`（网页拖放可能遗漏隐藏目录）。提交到 main。
3. Actions → Build Android APK v0.3.4 → Run workflow。成功后下载 artifact BMS-Ride20-Android-v0.3.4，解压安装 BMS_Ride20_Android_v0.3.4.apk。
4. 默认每次无密钥时生成测试签名，不保证 GitHub 不同运行间签名相同。覆盖失败需先备份手动容量等设置，再卸载旧版；不要公开私钥。

本地构建：JDK 17、Gradle 8.9、Android SDK 35/build-tools 35.0.0、OpenSSL，执行 `bash build-packages.sh android`。

## 验证范围
通过原有纯 Java 协议模拟测试、新版 60 分钟窗口、缺失值、最高速度、重置、联合能耗积分测试，以及 Java 语法解析、Shell 和 YAML 检查。未执行 Android SDK 编译，也未做真机 BLE/GPS 或界面验证。车辆静止时操作和安装，不将估算数据作为唯一驾驶依据。
